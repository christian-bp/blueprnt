## The design (binding; decision 10 chapter structure, replaces the combined view)

**Structure.** The model section mirrors /pay-mappings/[slug]/analysis exactly: a chapter registry module (`MODEL_CHAPTERS = ["criteria", "weighting", "method", "approval"] as const`, key-to-segment map, chapterHref/currentChapter helpers, per-chapter progress normalisation), routes `/model/criteria`, `/model/weighting`, `/model/method`, `/model/approval` under a shared `/model` layout, `/model` itself redirecting into the first chapter (so every existing link keeps working). The layout mounts, above the chapter page: the model spine (the AnalysisSpine anatomy: heading + help, one segmented progress bar whose segments are WEIGHTED by each chapter's total work, active chapter's segment at full strength, per-chapter count under the active segment via NumberFlow + rich message) and the numbered chapter tab row (the AnalysisChapterTabs anatomy: nav of Links, aria-current="page", layoutId underline with its OWN id, short numbered labels "1 Kriterier" .. "4 Godkännande"). REUSE IS THE RULE for this pair (owner direction 2026-08-20: "återanvänd komponenter mellan modell och kartläggning, uppfinn inte hjulet flera gånger"): the section-journey anatomy becomes SHARED components at the components root, consumed by both sections rather than mirrored. Concretely: (1) the segmented weighted progress bar + active-segment count row extracts to one shared primitive; (2) the numbered chapter tab row extracts to one shared component (props: items with key/label/href/current, the nav aria-label, a per-section layoutId; it owns the underline, overflow, aria-current, and number-recede treatment); analysis-spine and analysis-chapter-tabs re-point to these as thin per-section consumers (their i18n namespaces and registries stay their own), the kartläggning surface stays visually byte-identical and its tests stay green (adapt imports only, keep the load-bearing comments with the code they govern). The registries stay per-section (path shapes differ: /pay-mappings/[slug]/analysis vs /model) but share their helper SHAPE; extract a common helper only where the code is genuinely identical, never force a generic abstraction over different path grammars. The old two-tab model section row retires; the implementer verifies how the pay-mappings section integrates with `lib/section-pages.ts`/sidebar/command palette and mirrors that integration for the model section (one navigation language). The section uses the FULL viewport width with no max-width cap (owner amendment 7, 2026-08-20): a minimal local opt-out from the shell's width constraint, standard page padding kept, one consistent left edge for spine/tabs/framing/chapters; the first per-section application of the planned app-wide full-width rework.

**Chapter progress (derived on render, never stored, no visit tracking).** criteria: total = MODEL_MIN_CRITERIA (6), done = min(active count, 6); "complete" additionally requires the station's method checks (count 6-8, caps, coverage) to pass. weighting: total = 1 + the number of warning checks currently demanding a motivation, done = (budget check passes ? 1 : 0) + motivations present; born-passing is accepted (criteria enter at weight 3, so a fresh selection's budget is exact). method: total = active count + 1, done = criteria documented-and-approved + (materiality decided ? 1 : 0). approval: total 1, done = approval set. The weighted segments thereby make Metod honestly the big chapter, exactly the kartläggning bar's rationale.

**Kriterier chapter (/model/criteria).** The four dimension columns stay as built (dashed border, dimension title, count chip "1 av max 2" with the full-state variant swap, HelpMorphButton with the dimension question, hatch fill when empty, layout-shift-free states) but become display columns: NO droppable, NO on-page library lists, NO drag-and-drop anywhere. Each column carries an "add criterion" button (a section primary action per column) opening the library picker DIALOG scoped to that dimension: standard dialog anatomy; one row per unselected library criterion of that dimension showing name + shortUiText + the "rekommenderas för er bransch" chip + the amber overlap chip naming what it overlaps; choosing one calls `activateCriterion` (enters at weight 3, success toast, dialog closes, the new card animates into the column per docs/ui-animation.md); a FULL dimension's add button is replaced by the cap explained in words (flows state preconditions; backend still enforces). Resurrect the retired library-picker-dialog from git (00c04c0e^) as the base and rebuild its rows from the T1 card content. Selected-criterion cards in the columns show the name, the one-line shortUiText description inside the card (owner direction 2026-08-20: the lighter page has room for it), and as the ONLY action the shared RemoveConfirm morph in ItemActions (owner direction 2026-08-20: no one-item dropdown; the ghost trashcan arms into the inline confirm pill, zero layout shift, mirroring the method panel's criterion rows exactly, including how that precedent carries the ratings-deletion gravity) but NO weight row. The DnD machinery is deleted completely: `lib/builder-dnd.ts` (+tests), `hooks/use-build-dnd.ts`, the `dashboard.dnd.criterion.*` keys (five locales), DragOverlay wiring, keyboard-DnD tests, and the drag plumbing inside the cards (no-legacy: no dead props, no unused exports).

**Viktning chapter (/model/weighting).** The selected criteria grouped by dimension, each with the five-button ascending 1-5 weight row and the derived share. The budget block ("X av N viktpoäng fördelade" via NumberFlow, the balance status line, the save action gated balanced AND dirty, the AI weight-review entry in its pre-reserved slot) sits at the TOP of the chapter, below the framing line, reformatted to match how the Metod chapter opens; it is NOT sticky and NOT at the bottom (owner direction 2026-08-20 with screenshot: the page lost most of its content to the Kriterier chapter, so the action belongs at the top; the sticky-bottom rationale died with the combined page). NO criterion removal on this chapter (owner direction 2026-08-20): the weighting cards carry no remove menu; changing which criteria are in the model is the Kriterier chapter's job alone. The T2 pieces (placed-criterion-card, weight-point-row, and the budget bar's readout/gating/review pieces) rehome here otherwise unchanged in behavior. Empty state (no criteria selected yet): a short line pointing to the Kriterier chapter, never a bare page.

**Metod chapter (/model/method).** The existing method surface (per-criterion protokoll + bias documentation, the working-conditions materiality decision) under the chapter chrome with its framing line. **Godkännande chapter (/model/approval).** The existing ApprovalCard (twelve checks, approve, re-open state) moves here under its own framing line. Neither surface is rebuilt internally; they are re-homed and framed.

**Framing and copy.** Each chapter page opens with its own one-line §4.1 framing (the spine communicates sequence); the standalone BuildFraming block retires, its copy reused where it fits (delete orphan keys, five locales). The section still speaks of assembling "företagets blueprnt-modell". No bedömningsskala anywhere in the section. Every chapter ships its content-shaped skeleton (columns + hatch + real chrome for criteria; weight list + real budget bar for viktning; method/approval keep their existing skeletons re-homed).

**Assistant + docs.** ASSISTANT_PAGES: entries for the four chapter routes with true descriptions (/model/weighting returns as a real page; /model/approval is new; /model's entry describes the section + redirect). The docs corpus pages teaching the model section (criteria-and-scale, model-overview, weighting-and-point-budget, navigating-the-app, key-concepts, ai-weighting-review, plus a sweep) get their truth pass to the chapter world, `docs:sync` in the same change.

## Global Constraints

- English code/comments/commits; no em dashes; no attribution; conventional commits; comments state constraints only; stage only each task's files (the tree holds unrelated uncommitted docs).
- Every commit passes the full pre-commit gate. i18n parity across five locales for every key; help bodies within caps; never shell-pipe non-ASCII.
- House UI rules bind: design-system components only, dialogs' anatomy, toasts for CRUD, content-shaped skeletons (real static chrome, bars only for unknown data), no layout shift, Motion via `docs/ui-animation.md`, NumberFlow where a live number changes on screen (the budget bar's remaining-points readout qualifies).
- Keyboard accessibility is a hard requirement for the DnD (dnd-kit KeyboardSensor per the family-review-table precedent) and the click-to-add path must be fully equivalent.
- Backend changes in this phase: none expected beyond possibly a redirect; the phase-2 wires suffice. If a task believes it needs a backend change, it reports the need instead of making it.
