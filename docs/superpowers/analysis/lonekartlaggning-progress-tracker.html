03

Next up: the Iteration 2 rebuild (analysis detail views + the action layer)

Five system notes (2026-08-06) set the build front; M7 åtgärdsplan rides inside it

Entry conditions replace ⚪-everywhere: a lika arbete group is shown only when it has at least 1 woman AND at least 1 man AND women's mean below men's (grundlön primary, TCC parallel). Singletons are silently dropped everywhere including the gate; gender-pure groups move to an opt-in deep-dive; women-earn-more groups to a low-key info view. This amends ADR-0012's ⚪ + both-directions flagging: ADR-0015 required.

The detail views become individual-level: per-group member tables (name, gender mark, grundlön, TCC, diff vs men's mean in kr and %, women-first ascending default sort), swimlane dot plots with both mean reference lines and the gap annotated, and for likvärdigt arbete an explicit tvärnivå check (a woman on a higher level out-earned by a lower-level man, per pair, with track as the explaining factor). Notes' hue-coded genders, emoji flags and inline row buttons are adapted to the design system (texture/outline marks, PayGapFlagBadge, row ... menus).

The one remaining 3 kap. 11 § requirement lands with it: åtgärder (owner, planned date, cost, priority, status) and noteringar (three types) at group, individual and pair level, plus a dedicated åtgärdsöversikt tab with filters, inline audited status updates and a summary bar. Person links go through personPublicId only (Role != Person; erasure-safe by construction).

Plan: docs/superpowers/plans/2026-08-06-iteration-2-analysis-views-rebuild.md. Recommended slice order:

  1. A. Engine + entry conditions + gate: genderStats (min/median/mean/max/SD; the medians item folds in here), classifyEqualWorkGroup, crossLevelPairs, the reshaped gap query, ADR-0015.

  3. E. Åtgärder + noteringar: entities, audit wiring, dialogs, row affordances + badges.
  4. C. Likvärdigt detail + tvärnivå: level/track columns, per-woman pair aggregation, level-lane plot.
  5. F. Åtgärdsöversikt: the Actions tab, two filtered lists, status updates, summary bar.
  6. D. Könsrena deep-dive + women-earn-more info view: opt-in, outside gate and report.

Then the report module attaches to a finished survey: the internal kartläggningsrapport (PDF, the react-pdf kit already exists), the Art. 9 machine-readable export of the seven key metrics, the masked union report, the Art. 7 individual extract, and access/export logging at the export boundary. The engine's outcome classification is built so M8 inherits the exclusion boundary without rework.

04

Where the foundation is solid

The base the whole survey and pay-gap layer sits on is right.

The survey is a guided flow, not a table dump a chromeless wizard walks praxis questions and every flagged group step by step, and the analysis page is a searchable master-detail checklist that lands on the gate panel once everything required is done. The guide's "the system shall guide the user through the order" is the product's core bet, and the main differentiator vs. the incumbent's number-dense tables.
Import produces faithful monthly figures per-column monthly/annual basis (annual ÷12 at ingestion via one shared helper), the full PAY_COMPONENT_KINDS set ingested separately, and employment type captured, normalized across five locales, and audited like department.
Pay-component model is directive-correct (§A2) payRecords keeps basicMonthly separate from a typed components[] array, and TCC is derived on read, never stored (ADR-0002). The single most important seam, and it is right.
Role-evaluation engine is complete exact point-budget weighting (criteria × 3), deterministic normalize-to-0-100 + band assignment (Band 1 = highest), fixed track schema, per-individual level (ADR-0005), full anchor-role lifecycle.
GDPR / audit / tenant spine carries pay data every mutation writes a typed audit row, coded payload values render as localized labels (never raw enum codes), person-identifying fields are excluded from diffs and searchText, erasure hard-deletes child-first and pseudonymizes inside frozen snapshots, every function org-scoped fail-closed.
Route-level pseudonymization is correct people carry a short random publicId (never a name-slug, never the raw _id), externalRef is the employee number not a personnummer, no personnummer field exists anywhere.
05

Build order from here

The v2 sequence held: the survey/snapshot container first, then the mandatory gender-gap view, then the guided documentation flow. Steps 1-3 are done; the legal must-haves (action plan, reporting) now come before the guide's own P2 fördjupningar.

1. Kartläggning + data snapshot (Module 3) ✓ Shipped: the run entity, the immutable reference-date snapshot, the full status lifecycle with a completion gate, the preconditions gate, list + run management.
2. Deterministic gap engine (packages/core) ✓ Shipped: pure and AI-free; mean FTE-adjusted total-comp gap both directions, the four flags, quartile + age tallies, women-dominance. Still to add: median, percentiles, SD, the A4 variable-pay metrics.
3. P1 primary view + guided journey (Modules 4-6) ✓ Shipped, and beyond the plan: all three statutory comparisons, the review wizard + summary steady state, the reason catalog + praxis + klarmarkering documentation layer gating completion.
4. Action plan (Module 7) The åtgärdsplan entity with its legal fields, status, cost, follow-up; the 5% joint-pay-review trigger; wired into the existing completion gate.
5. Reporting + export (Module 8) Internal survey report, the Art. 9 JSON export (needs medians + A4), the de-identified union report, the individual Art. 7 extract, the archive package, access/export logging.
6. Extended comparisons (P2) + non-gender QC (P3) The configurable filtering engine, saved views, cohort/intersectional/trend analyses, off-policy outliers. Never a replacement for P1.

Small seams to close alongside: band-threshold calibration to the Bilaga B reference model, a working-conditions criterion, the samverkan participant-names erasure path (tracked go-live decision), and minor import additions (cost_center, manager reference, a grundlön = 0 flag).
