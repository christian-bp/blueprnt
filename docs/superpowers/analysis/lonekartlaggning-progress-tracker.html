Now building: the rollvärdering program (masterdokument)

The masterdokument (2026-08-18) governs the adaptable role evaluation model; design approved, phase 0 done

The constitution: four fixed dimensions (Kompetens, Ansträngning och komplexitet, Ansvar och påverkan, Arbetsförhållanden) as method law, a controlled 21-criterion library (5/5/7/4) replacing the 9-criterion standard template, selection of 6-8 non-overlapping criteria under per-dimension caps (2/2/3/1), and the §10.1 materiality test for working conditions (aktiv / prövad ej materiell, with a 0 = "omfattas inte" assessment for roles outside an active condition).

Stage separation without versioning (ADR-0023): the model stays live (ADR-0002 stands); approval is a status (draft / approved) whose only power is the gate: no role assessment against an unapproved method. Method-affecting edits re-open approval (one-click re-confirm when the §17.2 checklist is green); the kartläggning snapshot is the only freeze and grows into full method evidence. Assessment gets its own lifecycle: draft, locked (the reveal moment), calibrated; method drift is derived (lockedAt vs approvedAt), never stored.

Zones and profile requirements (ADR-0022): 12 levels in 4 zones (A 1-3 highest, D 10-12), profile criteria derived as the weight 4-5 set, per-zone minimum steps, deterministic placement (profile caps, never lifts, no overrides) with a derived "kalibrering krävs" queue: profile-limited placements, anchor-role deviations, stale locks. The 1-5 scale (anchors at 1/3/5) replaces 0-5.

04

Where the foundation is solid

The base the whole survey and pay-gap layer sits on is right.

The survey is a guided flow, not a table dump a chromeless wizard walks praxis questions and every flagged group step by step, and the analysis page is a searchable master-detail checklist that lands on the gate panel once everything required is done. The guide's "the system shall guide the user through the order" is the product's core bet, and the main differentiator vs. the incumbent's number-dense tables.
Import produces faithful monthly figures per-column monthly/annual basis (annual ÷12 at ingestion via one shared helper), the full PAY_COMPONENT_KINDS set ingested separately, and employment type captured, normalized across five locales, and audited like department.
Pay-component model is directive-correct (§A2) payRecords keeps basicMonthly separate from a typed components[] array, and TCC is derived on read, never stored (ADR-0002). The single most important seam, and it is right.
Role-evaluation engine is complete exact point-budget weighting (criteria × 3), deterministic normalize-to-0-100 + level assignment across the twelve levels in four zones (level 1 = highest, profile gates cap but never lift), fixed track schema, per-individual seniority (ADR-0005), full anchor-role lifecycle.
GDPR / audit / tenant spine carries pay data every mutation writes a typed audit row, coded payload values render as localized labels (never raw enum codes), person-identifying fields are excluded from diffs and searchText, erasure hard-deletes child-first and pseudonymizes inside frozen snapshots, every function org-scoped fail-closed.
Route-level pseudonymization is correct people carry a short random publicId (never a name-slug, never the raw _id), externalRef is the employee number not a personnummer, no personnummer field exists anywhere.

3. P1 primary view + guided journey (Modules 4-6) ✓ Shipped, and beyond the plan: all three statutory comparisons, the review wizard + summary steady state, the reason catalog + praxis + klarmarkering documentation layer gating completion.
